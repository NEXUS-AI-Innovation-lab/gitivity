3. Un connecteur Java complexe à écrire par service — chaque connecteur natif MidPoint doit implémenter toute la logique métier du service cible en Java + ConnId.

4. Pas de logique métier centralisée — impossible d'ajouter "si le user est stagiaire + rôle admin → alerte" sans modifier chaque connecteur.

5. Audit limité — MidPoint a son propre audit mais pas de traçabilité custom événement par événement avec stacktrace, retry count, DLQ.

6. Multi-cible non géré — si un user doit être sur LDAP ET MySQL, MidPoint lance deux opérations indépendantes sans coordination.
